# 1차 개발 구현 정리

작성일: 2026-11-02 

1차 범위 8개 기능을 모두 구현하고 확인해 **1차 개발을 완료했다.** 시세 제공처는 한국투자증권 KIS Open API를 사용한다.
실제 KIS 키로 삼성전자·SK하이닉스 2종목의 실시간 시세와 차트가 정상 동작하는 것을 확인했다 (11/2 장중).
추가로 목업과 같은 **종목 관련 뉴스**(NAVER API HUB 검색 API)를 붙이고, 이름만 언급된 기사·의견 글·정치 기사는 "기타" 탭으로 분리했다.
목업의 **전문가 투자의견**과 **최근 실적**(매출액·영업이익률 추가)도 KIS API로 붙였다.
목업의 **AI 대화 패널**은 화면만 먼저 옮겼다 (예시 답변, 외부 전송 없음. 실제 AI 연결은 2차).

## 2. 전체 구조

```
① 외부 API
   - KIS Open API (한국투자증권): 시세 · 투자의견 · 분기 재무
   - NAVER API HUB: 뉴스 검색

        ↓

② 백엔드 (Spring Boot :8085)
   - 시세: 수집 → 최신 시세 보관 → 브라우저로 전달 (Push 또는 Polling 2초)
   - 뉴스: 조회 → 종목 기사 / 기타 분류 (5분 저장)
   - 투자의견: 조회 → 증권사별 최신 의견 집계 (1시간 저장)
   - 분기 재무: 조회 → 분기 값 · 영업이익률 계산 (6시간 저장)

        ↓

③ 프론트 (Next.js :8086)
   - 종목 정보 · 티커 · 차트 · 관련 뉴스 · 투자의견 · 최근 실적
   - AI 대화 패널 (화면만, 예시 답변)
```

- API 키는 서버의 `.env`에만 둔다. 브라우저는 우리 서버만 호출한다.
- 키가 없으면 모의 데이터로 실행된다.

### 시세 데이터 형식 (`quote`, 주제 설명서 13.1 공통 이벤트와 같은 이름)
REST(`/quote`, `/api/quotes`)와 WebSocket Push(`{"type":"quote","data":{...}}`)가 같은 형식을 쓴다.

| 필드 | 내용 |
|---|---|
| `eventId` | 서버가 붙인 이벤트 번호 (종목코드-순번, 제공처 원천 ID 아님) |
| `symbol` · `name` · `market` | 종목코드(문자열, 앞자리 0 보존) · 종목명 · 시장(KOSPI 등) |
| `price` · `previousClose` | 현재가 · 전일 종가 |
| `changeAmount` · `changeRate` | 전일 대비 금액(원) · 등락률(%) |
| `open` · `high` · `low` | 시가 · 고가 · 저가 |
| `cumulativeVolume` | 누적 거래량 |
| `eventTime` · `receivedAt` | 체결 시각 · 서버 수신 시각 (ISO-8601 +09:00). 늦게 온 시세는 `receivedAt`으로 걸러낸다 |
| `source` · `dataMode` | 제공처 · 실제/모의 구분 (KIS / DEMO) |

숫자는 문자열이 아니라 숫자로 보낸다 (서버는 BigDecimal로 계산).

### 관련 뉴스 분류 규칙
서버가 종목명으로 최신 기사 100건을 받아 아래 순서로 나누고, 종목 기사와 기타를 각각 최신 20건씩 보낸다.

1. 제목이 의견 글(기고·칼럼·사설·상담실 등)이나 정치 기사(野·與·국힘·지도부 등)면 → **기타**
2. 제목에 종목명·줄임말·종목코드가 있으면 → **종목 기사** (삼성전자: 삼전·만전자·이재용 / SK하이닉스: 하이닉스·하닉·만닉스)
3. 요약에서 종목명이 나오는 문장에 주가·실적 단어(주가, 상승, 목표가, 영업이익, 배당, 점유율, % 등)가 있으면 → **종목 기사**
4. 그 외 (이름만 스친 기사) → **기타**

화면의 전체·실적·제품·기술·시장·투자 탭은 종목 기사만, 기타 탭은 걸러진 기사만 보여준다.

### 투자의견·실적 계산 규칙
- 투자의견 문구를 공백 제거·대문자로 맞춰 5단계로 나눈다 (BUY·매수·Outperform → 매수, Strong BUY → 강력 매수, 중립·Hold → 중립 …). 표에 없는 문구는 **기타**로 따로 세고 점수에서 뺀다.
- 점수 = (강력 매수 + 매수) / 분류된 의견 × 100. 증권사별 가장 최근 리포트 1건만 쓴다. 월별 추세는 그달 리포트를 모두 센다.
- KIS 투자의견은 1회 최대 100건이라, 100건이 차면 가장 오래된 날짜 이전으로 기간을 줄여 이어서 조회한다 (같은 리포트는 한 번만).
- KIS 분기 재무는 그해 누적값이라 `이번 분기 누적 - 직전 분기 누적`으로 분기 값을 만든다 (1분기는 그대로).
- 영업이익률 = 영업이익 / 매출액 × 100. 값이 없거나 분모가 0이면 0%가 아니라 `—`로 표시한다. KIS의 "값 없음" 표시 `99.99`도 빈 값으로 본다.

### AI 대화 패널 동작
- 오른쪽 열 맨 위 "AI에게 종목 질문하기" 버튼 → 화면 오른쪽에서 대화창이 열린다 (× · Esc · 바깥 클릭으로 닫기).
- 추천 질문 3개(영업이익률·매출과 이익·부채비율) 또는 직접 입력. Enter 전송, Shift+Enter 줄바꿈 (한글 조합 중 Enter는 전송하지 않음).
- 대화는 종목별로 따로 유지되고, 새로고침하면 지워진다. 답변은 고정 예시이며 외부로 전송하지 않는다.

## 4. 실시간 갱신 동작 방식

**서버**
1. 시작할 때 현재가를 한 번 받아 둔다.
2. KIS WebSocket에 연결해 체결 가격을 계속 받는다.
3. 새 가격이 오면 연결된 브라우저에 바로 보낸다.
4. 연결이 끊기면 자동으로 다시 연결한다.

**브라우저**
- **Push:** 서버가 보내 주는 가격을 바로 받는다. 끊기면 자동 재연결한다.
- **Polling:** 2초마다 서버에 가격을 물어본다.
- 둘 중 하나만 동작한다.
- 늦게 도착한 옛날 가격은 무시한다.

**호출 제한 대응** (KIS 초당 호출 한도)
- 요청 간격을 0.25초 이상 두고, 한도를 넘으면 잠시 쉬었다가 다시 요청한다.
- 접근 토큰은 파일에 저장해 재사용하고, 차트 데이터는 잠시 저장해 두고 재사용한다.
- 뉴스는 같은 종목을 5분 동안 저장해 재사용한다 (NAVER API HUB 하루 25,000회).
- 투자의견은 1시간, 분기 재무는 6시간 저장해 재사용한다. 화면을 처음 열 때 요청이 몰려도 한도 초과면 최대 4회 다시 요청한다.

## 5. 실행 방법

1. `backend/.env.example`을 복사해 `backend/.env`를 만들고 값을 채운다. **이 파일은 Git에 올리지 않는다.**
   ```properties
   MARKET_PROVIDER=kis
   KIS_APP_KEY=발급받은_APP_Key
   KIS_APP_SECRET=발급받은_APP_Secret
   NAVER_CLIENT_ID=NAVER_API_HUB_Client_ID
   NAVER_CLIENT_SECRET=NAVER_API_HUB_Client_Secret
   DB_USERNAME=root
   DB_PASSWORD=각자_MariaDB_비밀번호
   ```
   
   뉴스 키 발급: 네이버 클라우드 콘솔 → NAVER API HUB → Application 등록 (검색 → 뉴스 선택) → API 관리 → [인증 정보]
2. `start-backend.cmd` 실행 (JDK 21 자동 지정) → 로그에 `KIS 실제 데이터 모드로 실행합니다`가 나오는지 확인
   - `'mvnw.cmd' is not recognized` 오류가 나면 (한글 경로에서 폴더 이동 실패) `backend` 폴더에서 직접 `mvnw.cmd spring-boot:run`을 실행한다.
3. `start-frontend.cmd` 실행 → http://localhost:8086

키가 없어도 실행된다. 이때는 **모의 데이터 모드**로 화면 곳곳에 "모의 데이터"가 표시된다. 화면 개발용이며 실제 시세가 아니다.
