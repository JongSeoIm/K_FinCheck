# 2차 개발 구현 정리

작성일: 2026-11-05

2차 범위(회원가입·로그인, 관심 종목 DB 저장, 기업·실적 저장, Python AI 서버, 금융 챗봇 연결)를 구현했다.
1차 코드(Spring :8080, Next.js :3000) 위에 Python AI 서버(:8000)를 추가했다.
Spring 실행, KIS 웹소켓 연결, Kafka 구독, OpenDART 상장사 목록 수신, 챗봇 실제 답변, 장중 시세를 실제 환경에서 확인했다 (7번 참고).

## 2. 전체 구조

```
① 브라우저 (Next.js :3000)
   - 로그인 세션 쿠키를 포함해 Spring 만 호출

        ↓

② 백엔드 (Spring Boot :8080)
   - 회원, 관심 종목, 기업·실적, 대화 기록 DB
   - KIS 체결 수신 → Kafka → QuoteStore → Push / Polling

        ↓ POST /api/chat (최근 메시지 10개, 직전 질문 정보)

③ AI 서버 (FastAPI :8000)
   - 질문 분류 → Tool 선택 → Tool 호출 → 답변 수치 검사 → 출처 생성
   - Tool 은 Spring /api/tools 를 호출한다

        ↓ 조회 결과 + 답변 지침 + 최근 대화

④ OpenAI (GPT-5.4-mini)
   - 규칙으로 애매한 질문의 해석 보조
   - 조회 자료로 답변 문장 생성 (Tool 호출은 하지 않음)
```

- 실제 키는 `application-local.properties`, `ai_server/.env` 에만 둔다.
- RAG(벡터 검색)는 사용하지 않는다.

### 지원 종목

표시 종목은 8개다: 삼성전자, SK하이닉스, NAVER, 카카오, 현대차, 기아, LG화학, 삼성SDI.

- 티커, 실시간 구독, 검색, 차트는 `company` 테이블을 기준으로 한다.
- 비어 있는 `dart_corp_code` 는 OpenDART 상장사 목록으로 채운다.
- 챗봇은 OpenDART 상장사 목록으로 다른 국내 상장사도 현재가·실적·뉴스를 조회한다. 이 종목의 실적은 DB에 저장하지 않는다.

### 질문 분류 규칙

| 분류 | 예시 | Tool | OpenAI |
|---|---|---|---|
| 용어·개념 | 부채비율이 뭐야? | 없음 | 답변 |
| 현재가·등락 | 삼성전자 현재가 알려줘 | `get_stock_quote` | 답변 |
| 실적 | 삼성전자 최근 실적 알려줘 | `get_financial_result` | 답변 |
| 뉴스 | 삼성전자 관련 뉴스 알려줘 | `get_company_news` | 답변 |
| 기업 정보 | SK하이닉스는 어떤 회사야? | `get_company_info` | 답변 |
| 변동 원인 | 삼성전자 왜 올랐어? | 시세 + 뉴스 | 답변 |
| 전망 | 삼성전자 사도 돼? | 시세 + 실적 + 뉴스 | 답변, 단정하지 않음 |
| 기업 비교 | 삼성전자랑 현대차 현재가 비교해줘 | 지표에 맞는 Tool | 답변 |
| 애매한 표현 | 삼성전자 요즘 장사 잘돼? | 해석 결과에 따라 서버가 선택 | 해석 + 답변 |
| 다른 상장사 | 카카오뱅크 주가 알려줘 | 상장사 목록 조회 후 Tool | 답변 |
| 찾을 수 없는 기업 | 테슬라 주가 알려줘 | 없음 | 해석 후 안내 |
| 그룹 이름 | 삼성 어때? | 없음, 기업을 다시 질문 | 호출 안 함 |
| 금융과 무관 | 오늘 점심 뭐 먹지? | 없음, 고정 안내 | 호출 안 함 |

- 기업명이 없으면 대화창을 연 종목을 기준으로 한다.
- "그럼 실적은?", "거기 실적도 알려줘"는 앞 대화의 기업으로 이어서 답한다.
- "작년", "재작년"은 실적 조회 연도로 바꾼다.

### 실패·검사 처리

| 상황 | 처리 |
|---|---|
| 일부 Tool 실패 | 성공한 자료만 쓰고 확인하지 못한 자료를 안내 |
| 전체 Tool 실패 | OpenAI 호출 없이 자료를 확인할 수 없다고 안내 |
| 질문 해석 실패·불확실 | Tool 호출 없이 다시 질문 |
| 답변에 조회 자료에 없는 수치 | 한 번 다시 생성, 그래도 틀리면 조회 결과 문장으로 답변 |
| 답변 생성 실패 | 실패 문구와 다시 시도 표시, 대화에 저장하지 않음 |
| AI 서버 연결 실패 | 연결 실패 안내 |

### 응답 형식

```json
{
  "status": "answered",
  "answer": "답변 내용",
  "sources": [
    { "provider": "KIS", "label": "삼성전자 현재가", "basisAt": "2026-11-05T15:29:59+09:00", "url": null }
  ]
}
```

- `status`: `answered` / `out_of_scope` / `needs_clarification` / `no_data` / `failed`
- `sources` 는 OpenAI가 아니라 서버가 Tool 결과로 만든다. 용어 질문은 빈 배열이다.

### 대화 기록 관리

| 항목 | 동작 |
|---|---|
| 저장 | 질문과 답변을 삭제 전까지 MariaDB에 저장 |
| AI 전달 | 사용자와 AI 메시지를 합쳐 최근 10개 |
| 새 대화 | 새 대화방 생성, 이전 대화는 목록에 유지 |
| 삭제 | 선택한 대화와 메시지 삭제 |
| 로그아웃 | 화면만 비우고 다시 로그인하면 복원 |
| 서버 재시작 | DB 대화 유지 |
| 답변 실패 | 저장하지 않음 |

## 4. 챗봇 동작 방식

1. 브라우저가 Spring `POST /api/chat` 으로 대화방, 종목, 질문을 보낸다.
2. Spring이 로그인과 대화방 소유자를 확인하고 최근 메시지 10개를 DB에서 읽는다.
3. AI 서버가 질문을 분류한다. 금융과 무관한 질문과 그룹 이름은 여기서 바로 답한다.
4. 규칙이 애매한 질문은 OpenAI가 해석하고 서버가 지원 기업과 조건을 검사한다.
5. 서버가 필요한 Tool을 호출한다.
6. 조회 결과, 답변 지침, 최근 대화를 OpenAI에 보내 답변 문장을 받는다.
7. 답변 수치를 조회 자료와 대조하고, Tool 결과로 출처를 만든다.
8. Spring이 질문과 답변을 저장하고 브라우저로 전달한다.

## 5. 실행 방법

1. 키 파일을 준비한다. 이 파일들은 Git에 올리지 않는다.
   - `backend/src/main/resources/application-local.properties`: KIS, OpenDART, NAVER, DB 계정
   - `ai_server/.env`: OpenAI 키
2. 기존 DB가 있으면 백엔드를 끄고 `backend/sql/erd_맞춤_변경.sql` 을 한 번 실행한다.
3. 터미널을 따로 열어 순서대로 실행한다.

   | 순서 | 서버 | 실행 | 확인 |
   |---|---|---|---|
   | 1 | Kafka | `C:\kafka` 에서 `kafka-server-start.bat` | `Kafka Server started` |
   | 2 | Spring (8080) | `mvn spring-boot:run` | `Started StockApiApplication` |
   | 3 | 프론트 (3000) | `npm run dev` | `Ready` |
   | 4 | AI 서버 (8000) | `python -m uvicorn app.main:app --port 8000` | `Application startup complete` |

4. 테스트를 실행한다.
   ```bat
   cd backend
   mvn clean test
   cd ..\ai_server
   python -m pytest -q
   ```

## 6. 2차 점검에서 추가로 고친 부분

- 후속 질문: "그럼 실적은?", "거기 실적도 알려줘"를 지원하지 않는 기업으로 답하던 문제를 고쳤다.
- 금융 용어: "당기순이익이 뭐야?"를 기업명으로 오인하던 문제를 고쳤다.
- 회사 질문: `get_company_info` 를 챗봇 흐름에 연결했다.
- 비슷한 이름: "카카오뱅크"를 "카카오"로 인식하던 문제를 고쳤다.
- Polling: 응답을 받은 뒤 2초 뒤에 다음 요청을 보내도록 바꿨다.
- 저장소 이름: 보고서에 맞춰 `QuoteHub` 를 `QuoteStore` 로 바꿨다.
