# 2차 개발 구현 정리

작성일: 2026-11-05

2차 범위 6단계(MariaDB, 회원가입·로그인, 관심 종목 DB 저장, 기업·실적 저장, Python AI 서버, 금융 챗봇 연결)를 모두 구현했다.
1차 코드(Spring :8085, Next.js :8086) 위에 이어서 만들고, Python AI 서버(:8087)를 새로 추가했다.
실제 OpenDART·OpenAI 키로 실적 조회와 AI 답변을 확인했다. 장중 실시간 시세와 일부 화면 항목은 아직 확인하지 못했다 (6번 참고).

## 2. 전체 구조

```
① 브라우저 (Next.js :8086)
   - 로그인 쿠키(JSESSIONID)를 포함해 Spring 만 호출

        ↓

② 백엔드 (Spring Boot :8085)
   - 회원가입·로그인, 계정별 관심 종목, 기업·실적 DB
   - AI 대화 문맥 보관 (회원·종목별 최근 메시지 10개, 서버 메모리)

        ↓ POST /chat (X-Internal-Key)

③ AI 서버 (FastAPI :8087)
   - 질문 분류 → Tool 선택 → Tool 호출(각 5초) → 답변 수치 검사 → 출처 생성
   - Tool 은 다시 Spring API 를 호출한다

        ↓ 조회 결과 + 답변 지침 + 최근 대화

④ OpenAI (GPT-5.4-mini)
   - 받은 자료로 답변 문장만 생성 (Tool 선택·외부 API 호출은 하지 않음)
```

- API 키는 서버의 `backend/.env`에만 둔다. AI 서버도 같은 파일을 읽는다.
- `AI_INTERNAL_KEY`가 있으면 Spring 만 AI 서버를 호출할 수 있다.
- RAG(벡터 검색)는 사용하지 않는다.

| DELETE | `/api/watchlist/{symbol}` | 필요 | 삭제 후 전체 목록 |
| GET | `/api/companies/{symbol}` | | `{"company":{symbol, name, market, dartCorpCode}}` |

| POST | `/api/chat/messages` | 필요 | `{"symbol","question"}` → `{"status","answer","sources"}` |

오류는 1차와 같이 모두 `{"error":"메시지"}`.
- 로그인: 로그인 필요·로그인 실패 401, 아이디 중복 409, 형식 오류 400. 아이디와 비밀번호 중 무엇이 틀렸는지 알려주지 않는다.
- 실적: 공시 없음 404, 키 미설정·키 오류 503, 호출 한도 초과 429, 그 외 502.
- AI 서버: 연결 실패 503, 시간 초과 504, 그 외 502.

### DB 테이블 (`schema.sql`)

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `app_user` | `user_id`(PK), `login_id`(UNIQUE), `password_hash`, `nickname`, `regdate` | 비밀번호는 해시만 저장 |
| `company` | `symbol`(PK), `name`, `market`, `dart_corp_code`, `use_yn`, `regdate` | 삼성전자·SK하이닉스 |
| `watchlist` | `user_id`, `symbol`, `regdate` / PK(`user_id`,`symbol`) | 같은 종목 중복 방지, 계정 삭제 시 함께 삭제 |
| `financial_report` | `report_id`(PK), `rcept_no`, `symbol`, `bsns_year`, `reprt_code`, `fs_div`, `regdate` | `rcept_no + fs_div` UNIQUE로 중복 저장 방지 |
| `financial_value` | `report_id`, `account_id`, `account_nm`, `thstrm_amount`, `frmtrm_amount`, `currency` / PK(`report_id`,`account_id`) | 당기·전기 금액, 값이 없으면 NULL |

- `reprt_code`: 11013 1분기, 11012 반기, 11014 3분기, 11011 사업보고서. `fs_div`: CFS 연결, OFS 별도.

### 로그인·계정 분리
- `LoginInterceptor`가 `/api/watchlist/**`, `/api/chat/**`에서 세션을 확인한다. 시세·차트·뉴스 등 1차 API는 로그인 없이 조회한다.
- 관심 종목과 대화는 요청 값이 아니라 **세션의 회원 번호로만** 조회한다.
- 로그인할 때 세션 ID를 새로 발급한다. 세션은 서버 메모리에 있어 백엔드를 재시작하면 다시 로그인해야 한다.
- 가입 규칙: 아이디 영문 소문자·숫자 4~20자, 비밀번호 8~64자, 닉네임 2~20자.

### 실적 조회 규칙

| 질문 조건 | 조회 순서 |
|---|---|
| 연도·보고서 없음 | 올해 3분기 → 반기 → 1분기 → 작년 사업보고서 → 3분기 → 반기 |
| 연도만 | 그해 사업보고서 → 3분기 → 반기 → 1분기 |
| 보고서만 | 올해 → 작년 (사업보고서는 작년 → 재작년) |
| 연도 + 보고서 | 해당 보고서만 |

- 연결 실적이 있으면 연결, 없으면 별도 기준으로 답한다. 정정 공시가 저장되어 있으면 접수번호가 큰 공시를 쓴다.
- 2015년 이전 연도는 OpenDART를 호출하지 않고 안내한다.
- 분기·반기 보고서의 손익은 3개월 값, 전기는 전년 같은 분기다. 재무상태 항목의 전기는 직전 사업연도 말이다.
- 아직 공시되지 않은 보고서는 잠시 기억해 OpenDART를 반복 호출하지 않는다.

### 질문 분류 규칙 (`classifier.py`)

| 분류 | 예시 | Tool | OpenAI |
|---|---|---|---|
| 용어·개념 | 부채비율이 뭐야?, 영업이익 계산법 알려줘 | 없음 | 호출 |
| 현재가·등락 | 삼성전자 현재가 알려줘 | `get_stock_quote` | 호출 |
| 실적 | 삼성전자 최근 실적 알려줘 | `get_financial_result` | 호출 |
| 뉴스 | 삼성전자 관련 뉴스 알려줘 | `get_company_news` | 호출 |
| 기업 정보 | 삼성전자는 어떤 회사야? | `get_company_info` | 호출 |
| 변동 원인 | 삼성전자 왜 올랐어? | 시세 + 뉴스 (실적 단어가 있으면 실적도) | 호출 |
| 전망·매수 여부 | 삼성전자 사도 돼?, 구매해도 될까? | 시세 + 뉴스 (실적 단어가 있으면 실적도) | 호출, 단정하지 않음 |
| 기업 비교 | 삼성전자와 SK하이닉스 매출 비교해줘 | 지표에 맞는 Tool을 두 기업 모두 호출 | 호출 |
| 조건 부족 | 왜 올랐어?, 삼성전자와 SK하이닉스 비교해줘 | 없음, 기업·기간·지표를 다시 질문 | 호출 안 함 |
| 지원하지 않는 기업 | 카카오 주가, 테슬라 사도 돼?, 삼성카드 주가 | 없음, 지원 종목 안내 | 호출 안 함 |
| 조회할 수 없는 값 | 코스피 지수 얼마야?, 금리 얼마야? | 없음, 확인 가능한 범위 안내 | 호출 안 함 |
| 금융과 무관 | 오늘 점심 뭐 먹지?, 아이폰 가격 얼마야? | 없음, 고정 안내 1문장 | 호출 안 함 |

- 기업명이 없으면 **대화창을 연 종목**을 기준으로 한다.
- "그럼 작년은?", "하이닉스는?" 같은 후속 질문은 직전 질문의 유형을 이어받는다. 조건을 다시 물은 뒤 "매출로", "오늘"이라고 답하면 앞 질문과 합친다.
- 질문의 "작년", "올해"는 실제 연도로 바꿔 OpenAI에 전달한다.

### 실패·검사 처리

| 상황 | 처리 |
|---|---|
| 일부 Tool 실패 | 성공한 자료만 쓰고 확인하지 못한 자료를 안내 |
| 전체 Tool 실패 (장애) | OpenAI 호출 없이 "잠시 후 다시 질문해 주세요" 안내 |
| 자료가 없음 (404, 관련 기사 없음) | OpenAI 호출 없이 부족한 자료와 확인 가능한 범위 안내 |
| 답변의 비율·금액(조·억)이 조회 자료에 없음 | 한 번 다시 생성, 그래도 없으면 답변을 표시하지 않음 |
| AI 서버 연결 실패 | "AI 서버에 연결할 수 없습니다." 표시 |

답변 지침과 질문 종류별 분량(2~4문장 등)은 `prompts.py`에 PDF 내용대로 넣었다. Markdown이 섞여 오면 서버에서 지운다.

### 응답 형식

```json
{
  "status": "answered",
  "answer": "답변 내용",
  "sources": [
    { "provider": "KIS", "label": "삼성전자 현재가", "basisAt": "2026-11-04T15:30:00+09:00", "url": null }
  ]
}
```

- `status`: `answered` / `need_more_info` / `out_of_scope` / `unavailable` / `error`
- `sources`는 OpenAI가 아니라 AI 서버가 Tool 결과로 직접 만든다. 용어 질문은 빈 배열이다.

### 대화 문맥 관리 (현재 구현)

| 항목 | 동작 |
|---|---|
| 유지 범위 | 회원·종목별로 사용자와 AI 메시지를 합쳐 최근 10개 |
| 새 대화 버튼 | 해당 종목의 문맥과 화면 대화 삭제 |
| 로그아웃·세션 만료 | 그 회원의 대화 모두 삭제 |
| 서버 재시작 | 서버 메모리에만 있어 사라짐 |
| 조회 실패·서버 오류 | 문맥에 남기지 않음 |

### 2차 점검에서 추가로 고친 부분
- **시세 체결 시각:** KIS 현재가 응답에 체결 시각이 없어 최근 분봉으로 채우고, 확인하지 못하면 조회 시각임을 표시한다.
- **뉴스 분류:** 자회사 기사·환율 문장·시황 단어로 잘못 분류되던 기사를 걸러 낸다. 챗봇은 제목에 기업명이 나온 기사를 먼저 쓴다.
- **후속 질문:** "그럼 작년은?"에 그 전해 금액으로 답하던 문제를 고쳤다.
- **같은 뜻의 질문:** "테슬라 사도 돼?"와 "테슬라를 구매해도 될까?"가 같게 처리된다.
- **분기 실적:** 연도 없이 "1분기 실적"을 물어도 해당 분기 보고서를 찾는다.
- **다른 회사·없는 자료:** 삼성카드, 코스피 지수, 금리 질문에 대화 중인 종목의 시세로 답하지 않는다.

## 4. 챗봇 동작 방식

1. 브라우저가 Spring `POST /api/chat/messages`로 종목과 질문을 보낸다.
2. Spring이 로그인을 확인하고 최근 메시지(최대 10개)를 꺼내 AI 서버로 보낸다.
3. AI 서버가 질문을 분류한다. 무관한 질문, 조건 부족, 지원하지 않는 기업은 여기서 바로 답한다.
4. 필요한 Tool을 동시에 호출한다 (각 5초 제한).
5. 조회 결과, 답변 지침, 최근 대화를 OpenAI에 보내 답변 문장을 받는다.
6. 답변의 수치를 조회 자료와 대조하고, Tool 결과로 출처를 만들어 돌려준다.
7. Spring이 질문과 답변을 문맥에 추가하고 브라우저로 전달한다.

**브라우저**
- 로그인하지 않으면 AI 버튼을 눌렀을 때 로그인 화면으로 이동한다.
- 패널을 열면 서버가 기억 중인 대화를 불러온다. 종목별 대화는 섞이지 않는다.
- 답변 아래에 제공처, 자료명, 기준 시점, 원문 링크를 표시한다.

## 5. 실행 방법

1. `backend/.env.example`을 복사해 `backend/.env`를 만들고 1차 값에 아래를 추가한다. **이 파일은 Git에 올리지 않는다.**
   ```properties
   DART_API_KEY=발급받은_40자리_OpenDART_키
   OPENAI_API_KEY=발급받은_OpenAI_키
   AI_INTERNAL_KEY=아무_긴_문자열
   ```
   OpenDART 키 발급: opendart.fss.or.kr → 인증키 신청/관리

   3306 포트가 MariaDB가 아니면 `DB_URL`을 지정한다. `SELECT VERSION();`으로 먼저 확인한다. 이 PC는 3306이 MySQL 8.4, 3300이 MariaDB다.
   ```properties
   DB_URL=jdbc:mariadb://localhost:3300/stockdb?createDatabaseIfNotExist=true&allowPublicKeyRetrieval=true
   ```
2. 서버 3개를 실행한다.

   | 순서 | 서버 | 실행 | 확인 |
   |---|---|---|---|
   | 1 | Spring (8085) | `start-backend.cmd` | `Tomcat started on port 8085` |
   | 2 | AI 서버 (8087) | `start-ai.cmd` (처음 한 번은 패키지 설치) | `OpenAI 모델 사용 가능: gpt-5.4-mini` |
   | 3 | 프론트 (8086) | `start-frontend.cmd` | http://localhost:8086 |

   - AI 서버 로그에 `OpenAI 모델 확인 실패`가 나오면 키가 틀렸거나 그 계정에서 모델을 쓸 수 없는 경우다.
   - 키가 없어도 서버는 켜지고, 실적·AI 답변에서 키 미설정 안내가 나온다.

3. 점검을 실행한다.
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\test-phase2-api.ps1
   powershell -ExecutionPolicy Bypass -File scripts\test-phase2-chat.ps1
   cd ai-server; .\.venv\Scripts\python.exe -m pytest -q tests
   ```

`test-phase2-api.ps1`은 실행할 때마다 테스트 계정을 만든다. 아래 SQL로 지우면 관심 종목도 함께 지워진다.
```sql
DELETE FROM app_user WHERE login_id LIKE 't2a%' OR login_id LIKE 't2b%';
```
