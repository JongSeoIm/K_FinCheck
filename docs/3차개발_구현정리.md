# 3차 개발 구현 정리

작성일: 2026-11-06

KIS 실시간 시세를 **Kafka**로 전달하고, 차트 전 주기, 연간 실적 화면, 재무 지표, 대화 기록 저장, Spring Security, 전달 방식 측정, OpenAI 질문 해석 보조, AI 공시 답변을 구현했다. 지원 종목은 8개다.
구조는 개발예정보고서의 시스템 구성도에 맞춰 시세 수신, Kafka Producer·Consumer, QuoteStore를 모두 Spring Boot 안에 두었다.
실제 KIS 키로 장중에 체결이 `docker-compose.yml`로 띄운 Kafka 브로커를 거쳐 화면까지 오는 것을 확인했다. 브로커 중단·복구는 모의 체결로 확인했다 (6번 참고).

## 2. 전체 구조

```
① KIS WebSocket
        ↓
② Spring Boot (:8085)
   - 시세 수신: KisRealtimeClient (끊기면 재연결·재구독)
   - Kafka Producer: QuoteKafkaProducer
        ↓ stock-quotes-v1 (키: 종목 코드) / stock-feed-heartbeat-v1 (5초마다 확인)
③ Kafka
        ↓
④ Spring Boot
   - Kafka Consumer: QuoteKafkaConsumer
   - QuoteStore: 중복·역순 제거, 최신 시세, 초·분봉 집계 (메모리)
   - 시세 전달: Push 0.5초 간격 / Polling 조회 응답
        ↓
⑤ 프론트 (Next.js :8086) · AI 서버 (FastAPI :8087, 시세·실적·공시 Tool은 Spring 조회)
```

## 3. 기능별 구현

| # | 기능 | 구현 내용 |
|---|---|---|

| 2 | 장애 처리 | 재연결·재구독, 발행 재시도, 중복·역순 제거, 연결 상태 표시 |

| 6 | 연간 실적 | OpenDART 사업보고서, 전년 대비 증감률·비교 막대, 흑자·적자 전환, 원문 링크 |
| 7 | 재무 지표 | 영업이익률, 부채비율, 유동비율, 매출 증감률. Spring이 계산해 화면과 AI 답변에 같이 사용 |

| 9 | Spring Security | 서버 세션 인증, 관심 종목·챗봇 접근 제어, CSRF 토큰 |
| 10 | 회원 흐름 | 가입 후 로그인 화면으로 이동, 로그인 후 이전 종목으로 복귀, 로그인 메뉴 상단 왼쪽 |

| 13 | 뉴스 패널 | 최신순 최대 10개, 중복 기사 정리, 5분 서버 캐시, 출처·원문 링크, 기사 전문 아님 안내 |

| 15 | AI 답변 표시 | 카드·표·막대·공시 링크, 실패 시 다시 시도 |
| 16 | 지원 종목 | 8개. 시세·차트·실적·뉴스·AI 질문에 모두 적용 |
| 17 | AI 공시 답변 | 뉴스·주가 변동·전망 질문은 시세와 OpenDART 공시로 답변 |

### DB 구조 (`schema.sql`, 서버 시작 시 자동 적용)

보고서의 DB 구조대로 테이블 7개를 사용한다. 시세 테이블은 두지 않는다.

| 테이블 | 주요 컬럼 |
|---|---|
| `company` | `stock_code`, `company_name`, `market_type`, `dart_corp_code`, `created_at`, `updated_at` |
| `app_user` | `user_id`, `login_id`, `password_hash`, `nickname`, `created_at`, `updated_at` |
| `watchlist` | `user_id`, `stock_code`, `created_at` |
| `financial_report` | `report_id`, `stock_code`, `receipt_no`, `business_year`, `report_code`, `fs_div`, `collected_at` |
| `financial_value` | `value_id`, `report_id`, `account_code`, `account_name`, `source_account_id`, `source_account_name`, `current_amount`, `previous_amount`, `currency`, `value_status` |
| `chat_conversation` | `conversation_id`, `user_id`, `stock_code`, `stock_name`, `title`, `created_at`, `updated_at` |
| `chat_message` | `message_id`, `conversation_id`, `role`, `content`, `context_content`, `response_json`, `created_at` |

- 회원 번호·공시 번호 등은 `BIGINT UNSIGNED`, `business_year`는 `SMALLINT UNSIGNED`다.
- 회원 컬럼 길이는 `login_id` 50, `password_hash` 255, `nickname` 30이다.
- `financial_report`는 수집한 지 1시간이 지나면 다시 수집한다.
- `financial_value`는 `report_id + account_code`가 UNIQUE이고, `value_status`는 AVAILABLE / MISSING이다.
- `account_name`은 공통 이름(매출액), `source_account_name`은 공시에 적힌 이름이다. API의 `accountName`은 공시에 적힌 이름을 준다. OpenDART 주요계정 API는 계정 ID를 주지 않아 `source_account_id`는 비어 있다.
- 금액 컬럼은 `DECIMAL(30,2)`이고 코드에서는 원 단위 `Long`으로 읽는다. 지금 저장하는 값은 모두 원 단위 정수다.
- `chat_conversation`은 회원·종목별 여러 개이고, 제목은 80자, 시각은 `DATETIME(6)`이다.
- `chat_message`의 `content`는 화면용, `context_content`는 AI 문맥용(최대 16,000자)이고, `response_json`에는 status·sources·visuals를 저장한다. `context_content`에는 `content`와 같은 내용이 들어간다.
- 화면과 AI 서버가 쓰는 API 응답 이름은 `symbol`, `name`, `market`, `bsnsYear` 등이다.

### QuoteStore 봉 집계 규칙
- 수신한 모든 체결을 체결 시각 구간으로 나눠 OHLC를 만든다.
- 봉 거래량은 누적 거래량의 차이다. 연결 후 첫 체결은 기준값이라 0이고, 누적이 줄면 새 거래일로 본다.
- 체결이 없는 구간에는 봉을 만들지 않는다.
- 체결이 수 초 늦게 오므로 구간이 끝나고 5초 뒤에 봉을 닫는다. 이미 닫힌 구간에 더 늦게 온 체결은 버린다.
- 실시간 봉은 DB에 저장하지 않는다. 초봉은 서버 메모리에만 있어 재시작하면 사라진다.
- 분봉은 당일 KIS 분봉과 수신 봉을 합친다. 이전 날짜의 분봉은 제공하지 않는다. 일봉 이상은 KIS 조회를 쓴다.

### AI 공시 답변

- 뉴스·기사·공시 질문은 최근 공시의 이름과 접수일로 답하고, 기사는 화면의 관련 뉴스 패널을 안내한다.
- 주가 변동·전망 질문은 시세와 공시로 답한다. 자료로 원인을 확인할 수 없으면 그렇다고 말한다.
- 공시는 조회할 때마다 OpenDART에서 받고, 답변 아래에 공시 카드와 원문 링크를 표시한다.
- 공시 이름에 없는 세부 내용은 덧붙이지 않는다.

### 질문 해석 보조 (`interpreter.py`)

| 단계 | 담당 | 내용 |
|---|---|---|
| 1 | 규칙 (`classifier.py`) | 질문을 먼저 분류. 단어가 분명하면 여기서 끝나고 OpenAI 해석을 부르지 않음 |
| 2 | OpenAI | 규칙에 걸린 단어가 없어 기본값으로 판단한 질문만 해석. 질문 종류·기업·연도·보고서·비교 지표를 정해진 형식으로 반환 |
| 3 | 서버 | 지원 종목에 없는 코드, 범위를 벗어난 연도를 버리고 질문 종류에 맞는 Tool 선택 |
| 4 | OpenAI | 조회 결과로 답변 문장 생성 |

- 예: "이 회사 돈 잘 벌어?" → 실적 질문, "쏘카 사도 돼?" → 지원하지 않는 기업 안내, "안녕" → 범위 안내.
- OpenAI는 Tool을 고르거나 외부 API를 부르지 않는다. 해석에 실패하면(시간 제한 8초) 규칙의 판단을 그대로 쓴다.
- "오늘 점심 뭐 먹지?"처럼 규칙으로 분명한 무관 질문은 OpenAI를 호출하지 않는다. 다만 "안녕"처럼 금융 단어가 없어 기본값으로 판단한 질문은 해석을 한 번 호출한다.

### 장애 처리

| 중단 대상 | 처리 |
|---|---|
| KIS 연결 | 5초부터 최대 60초 간격으로 재연결·재구독, 화면에 `KIS 연결 끊김` 표시, 시세는 KIS REST로 보충 |
| Kafka | 15초 뒤 화면에 `Kafka 연결 끊김` 표시, 발행을 재시도하고 실패를 성공으로 세지 않음. 대기열이 차면 오래된 시세부터 버림, 시세는 REST로 보충 |
| Spring Boot | 재시작 후 마지막 처리 위치부터 소비, 중복·역순 제거 |

중단 구간의 체결은 복구를 보장하지 않는다.

## 4. 대화 문맥 동작

- 종목마다 대화방을 여러 개 둔다. 패널을 열면 가장 최근 방을 열고 메시지를 100개까지 복원한다.
- AI에게는 보고 있는 방의 최근 메시지 10개만 보낸다.
- 새 대화는 기존 대화를 지우지 않는다. 대화방은 첫 질문을 보낼 때 만든다.
- 제목은 `새 대화`로 시작해 첫 답변 저장 때 첫 질문으로 바뀐다. 답변이 실패하면 빈 방이 남을 수 있다.
- 대화방은 목록에서 고르거나 확인 후 삭제한다. 로그아웃해도 남고, 답변을 기다리는 동안에는 바꾸거나 지울 수 없다.
- 자료 없음·조회 실패 안내는 저장한다. AI 답변 실패와 서버 오류·시간 초과는 저장하지 않는다.
- 조회 자료는 카드·표·막대·공시 링크로 표시한다. AI 서버가 Tool 결과로 만들어 `response_json`에 저장한다.
- 답변이나 대화 불러오기가 실패하면 안내와 다시 시도 버튼을 표시한다.

## 5. 실행 방법

1. `backend/.env`에 1·2차 값과 함께 `KAFKA_BOOTSTRAP_SERVERS=localhost:9092`를 둔다. 비워 두면 같은 값을 쓴다.
2. 아래 순서로 실행한다.

   | 순서 | 서버 | 실행 | 확인 |
   |---|---|---|---|
   | 1 | Kafka (9092) | Docker Desktop 실행 후 `docker compose up -d` | `docker ps`에 `broker` |
   | 2 | Spring (8085) | `start-backend.cmd` | `Tomcat started on port 8085` |
   | 3 | AI 서버 (8087) | `start-ai.cmd` | `OpenAI 모델 사용 가능` |
   | 4 | 프론트 (8086) | `start-frontend.cmd` | http://localhost:8086 |

   - 토픽은 Spring Boot가 시작할 때 만든다 (`stock-quotes-v1` 파티션 3개). Kafka를 먼저 켠다.
   - Spring Boot가 켜진 채로 `docker compose down` 후 다시 올리면 토픽이 파티션 1개로 자동 생성된다. 시세는 계속 오고, Spring Boot를 재시작하면 3개로 돌아온다. 잠시 멈출 때는 토픽이 남는 `docker compose stop`을 쓴다.
   - Docker Desktop 없이 WSL에 직접 설치한 Docker는 열린 WSL 세션이 없으면 약 30초 뒤 WSL과 함께 브로커가 멈춘다. 쓰는 동안 터미널에서 `docker compose logs -f broker`를 열어 둔다. 이 명령은 브로커를 중지하면 함께 끝나므로 다시 시작한 뒤 다시 실행한다.
   - KIS 키가 없으면 Spring Boot가 모의 체결을 발행한다. Kafka 없이 켜면 화면에 `Kafka 연결 끊김`이 나오고 시세는 REST로 보충된다.
   - KIS 실시간은 키 하나로 한 곳만 접속하는 것을 전제로 하므로 Spring Boot 서버는 하나만 실행한다.
   - 이전 버전의 DB를 쓰고 있으면 백엔드를 끄고 `scripts/migrate-column-names.sql`, `scripts/migrate-db-definition.sql`을 순서대로 한 번씩 실행한다. 새 DB는 실행하지 않는다.

3. 전달 방식 비교는 장중에 실행한다. 조건을 바꾸려면 `--seconds`, `--symbols`를 쓴다.
   ```bash
   node scripts/compare-feed.mjs --seconds 60 --symbols 005930,000660
   ```
