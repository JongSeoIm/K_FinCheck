## 6. 캔들 차트 SVG 렌더링 버그 수정 및 주기 선택 UI 개편 (완료)
- **현상**:
  1. Recharts 3.x 환경에서 `<Customized component={CandlestickLayer} />` 내부에서 데이터 객체 참조가 비어 있어 캔들이 렌더링되지 않던 문제.
  2. KIS 실전 API의 초당 거래건수 제한(1~2건)으로 인해 빠른 탭 전환 또는 다중 호출 시 `500 EGW00201: 초당 거래건수를 초과하였습니다` 에러가 발생하여 차트 데이터가 비어버리던 문제.
  3. 주기 선택 UI가 어두운 캡슐 박스 형태로 되어 있어 `캔들 차트 · 선 차트` 텍스트 링크 스타일과 이질감이 있던 문제.
- **수정 및 보완 파일**:
  1. `backend/src/main/java/com/kfincheck/client/KisApiClient.java`:
     - KIS API 호출 간 최소 요청 간격(250ms) 제어(`paceRequest`) 추가.
     - `EGW00201`(초당 거래건수 초과) 오류 수신 시 600ms 대기 후 자동 1회 재시도(Backoff Retry) 로직 추가로 오류 완전 방지.
  2. `backend/src/main/java/com/kfincheck/service/StockService.java`:
     - 단기 인메모리 캐시 적용 (현재가 3초, 차트 데이터 25초)으로 연속 탭 전환 시 중복 KIS 호출을 제거하고 0ms 즉각 응답.
  3. `stock_dashboard/src/app/components/StockChart.jsx`:
     - `CandlestickLayer`에 `candles` 데이터를 명시적으로 주입하고, Recharts가 계산한 포인트(`points`)와 스케일을 이중으로 참조하여 캔들 막대(양봉 빨강 `#c43b3b`, 음봉 파랑 `#1769aa`, 꼬리선)가 즉시 렌더링되도록 수정.
     - 주기 선택 UI를 `캔들 차트 · 선 차트`와 동일한 글씨 클릭형 밑줄 탭(`1분 ⌄ · 일 · 주 · 월 · 년`)으로 변경.
  4. `stock_dashboard/src/app/globals.css`:
     - 검은색 캡슐 박스를 제거하고 `.range-tabs` 텍스트 버튼, 파란색 밑줄(`border-bottom: 2px solid #1769aa`), 중간 구분점(`·`), 화이트 톤 드롭다운 팝오버 스타일 적용.
- **검증 결과**:
  1. 백엔드 연속 호출 및 캐시 검증: 현재가 및 일·주·월봉 API 연속 호출 시 `EGW00201` 오류 없이 HTTP 200 정상 반환 확인.
  2. 백엔드 단위 테스트: `mvn test` 전체 통과 (`BUILD SUCCESS`).
  3. 프론트엔드 프로덕션 빌드: `npm run build` 통과 (`✓ Compiled successfully in 5.0s`).
  4. 백엔드 및 프론트엔드 데몬 정상 구동 중 (`http://localhost:3000`, `http://localhost:8080`).

- 실적에 직접 연결된 사업연도와 과거 주가 분석 기간을 구분한다. ‘지난주 하락 이유와 실적’처럼 섞인 요청도 현재 시세로 과거 원인을 설명하지 않도록 차단한다.
- **검증**: Python 테스트 35개·문법 검사 통과. 회귀 테스트에서 기업명 별칭, 미지원 기업, 현재가·실적 후속 질문, 사용자·대화별 문맥 분리, 과거 기간 제한을 확인했다. 실제 API에서 삼성전자 현재가 다음 ‘그럼 하이닉스는?’이 SK하이닉스 카드로 반환됨을 확인했다.
- **범위**: 이번 수정은 검토에서 확인된 세 오류 대상이다. 새 대화·로그아웃 시 문맥 초기화 정책과 배포용 FastAPI 접근 제한은 별도 작업이다. 자연어 처리는 규칙 기반이므로 다양한 표현에 대한 추가 점검이 필요하다.
- FastAPI 재시작으로 반영했다. 프론트엔드 변경·브라우저 UI 검증·커밋은 하지 않았다.

## 16. 줄임말·오타 정규화 및 AI 질문 해석 보완 (2026-11-03)
- 삼전·하닉 별칭과 주까·현제가 등 자주 쓰는 오타를 정규화한다. 명사형 질문은 기존 조회 규칙으로 처리하며, 기업만 지정한 짧은 질문은 직전 조회 문맥을 적용하거나 필요한 정보를 다시 묻는다.
- 규칙으로 해석하기 어려운 금융 질문에만 OpenAI 구조화 응답으로 기업·질문 종류·기간·지원 조건 후보를 받는다. 일반적인 무관 질문은 해석 API에 보내지 않는다.
- AI 역할을 최종 답변 작성에서 ‘모호한 질문의 해석 후보 제공’까지 확장했다. 지원 기업·명시 기업 일치·오타 유사성·기간·실적 조건은 서버에서 다시 검사하고 Tool 실행은 서버가 결정한다.
- ‘삼성’처럼 여러 기업을 뜻할 수 있는 표현, 미지원 기업, 해석 실패·불확실한 입력은 확인 안내를 반환한다. 해석 API는 8초 제한을 적용하고 인증키·수치 생성이나 외부 API 실행을 맡기지 않는다.
- **검증**: Python 테스트 41개·문법 검사 통과. 실제 API에서 ‘삼전 주까’, ‘삼성젼자 주가’의 현재가 카드, ‘삼성’의 확인 질문, ‘애플 현재가’의 기업 확인 안내를 확인했다.
- **대화 정책 확인**: 기존 사용자·종목별 대화 분리 방식을 유지했다. 종목 이동 자체로 기존 대화를 삭제하지 않는다. 화면 대화는 새로고침 시 사라지며 서버 문맥 초기화 정책은 별도 작업이다.
- FastAPI 재시작으로 반영했다. 프론트엔드 변경이 없어 화면 빌드는 생략했고 브라우저 UI 검증·커밋은 하지 않았다.

## 17. 계정·종목별 대화 DB 보관 및 새 대화·기록 관리 (2026-11-03)
- `chat_conversation`, `chat_message` 테이블을 추가했다. 생성 SQL은 `backend/src/main/resources/db/chat-history.sql`이며 Spring 시작 시 기존 테이블을 덮어쓰지 않고 생성한다.
- Spring은 로그인 계정 소유권과 대화방 종목을 검증한 후 질문·답변을 한 트랜잭션으로 저장한다. 답변의 출처·카드·표·기사 데이터와 문맥용 정규화 질문을 함께 저장한다.
- Python DB 접근은 추가하지 않았다. Spring이 현재 대화방의 최근 메시지 10개를 전달하며, 이 경로에서는 Python 메모리를 사용·갱신하지 않는다. 빈 이력을 전달하면 새 문맥으로 시작한다.
- 종목 이동·새로고침·재로그인 후 저장 대화를 조회한다. 브라우저에는 마지막 선택한 대화방 ID만 기억하고 메시지 내용은 DB에서 복원한다.
- 헤더 아래 텍스트형 ‘새 대화 · 이전 대화’를 추가했다. 새 대화는 기존 기록을 보관하고 별도 방을 만든다. 목록에서 이전 대화를 선택하거나 삭제 확인·취소를 할 수 있다.
- 삭제는 선택한 대화방과 그 메시지를 DB에서 제거하는 방식이다. 삭제 완료 후 서비스에서 복구하는 기능은 없다. 다른 대화방에는 영향을 주지 않는다.
- API: `GET/POST /api/chat/conversations`, `GET /api/chat/conversations/{id}/messages`, `DELETE /api/chat/conversations/{id}`. 모두 로그인 전용이다.
- **검증**: Python 42개, Spring 관련 6개 테스트 통과. 실제 MariaDB에 연결한 테스트에서 소유권·DB 재조회·카드 보존·최근 문맥 제한·대화별 삭제·새 대화 분리 및 로그인 API 흐름을 확인했다. 테스트용 데이터는 롤백했다. JSX ESLint와 Next.js 빌드 통과, 최종 readOnly 속성 추가 후 공백 검사 통과. 서버 세 개 HTTP 200 확인.
- **미실행**: 브라우저에서 새 관리 UI의 육안·클릭 검증은 미실행. Spring·FastAPI 재시작으로 반영했다.
- 이번 기능 적용 전 메모리에만 있던 대화는 자동 이관하지 않는다. DB에 저장되는 신규 대화부터 복원이 가능하다. 테이블 정의서·ERD는 새 테이블 반영이 필요하다. 커밋하지 않았다.
