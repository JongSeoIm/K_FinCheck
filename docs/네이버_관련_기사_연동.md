# 네이버 관련 기사 연동

## 현재 코드

- 선택한 종목 코드를 Spring Boot `GET /api/stocks/{stockCode}/news`로 전달한다.
- 서버는 종목 코드를 기업명으로 바꿔 NAVER API HUB 뉴스 검색을 호출한다.
- 현재 화면의 국내 기업 8개를 지원한다. 최신순 최대 10개이며 기업명 검색 결과이므로 모든 항목의 금융 관련성을 별도 검증하지는 않는다.
- 검색 결과의 제목·설명·게시 시각·원문 링크를 표시한다. 설명은 네이버 검색 결과에 포함된 문구이며 AI가 생성한 기사 요약이 아니다.
- 기사 전문을 크롤링하거나 저장하지 않는다. 검색 응답의 HTML 강조 태그와 중복 링크를 정리하고 HTTP/HTTPS 링크만 허용한다.
- 같은 기업의 성공 결과는 서버 메모리에서 5분간 재사용한다. 화면 진입·종목 전환·실패 후 재조회 시 요청하며 자동 5분 주기 호출은 하지 않는다.
- 키 미설정, 미지원 종목, 인증·조회 한도·통신 오류, 검색 결과 없음 상태를 구분한다.

## 로컬 키 설정

Git에서 제외된 `backend/src/main/resources/application-local.yml` 맨 아래에 추가한다. 기존 KIS·OpenDART 설정을 유지한다.

```yaml
naver-news:
  client-id: YOUR_CLIENT_ID
  client-secret: YOUR_CLIENT_SECRET
```

NAVER API HUB에서 발급한 값을 사용한다. 구 NAVER Developers 인증 정보와 혼용하지 않는다. 실제 값은 채팅·프론트엔드·Git에 넣지 않는다.

설정 후 백엔드를 재시작하고 화면에서 종목을 선택한다. 프론트엔드의 백엔드 주소 설정은 기존 시세·실적과 동일하다.

## 검증 상태

- 관련 단위/API 테스트 3개와 NewsFeed ESLint를 통과했다.
- 2026-11-02 사용자 로컬 인증 설정으로 삼성전자·SK하이닉스 각각 실제 기사 10개를 조회했다. 같은 기업 재조회 시 fetchedAt 일치로 5분 캐시 재사용을 확인했다.
- 별도 검증 서버·브라우저에서 종목별 제목·설명·게시 시각·새 탭 원문 링크와 종목 전환, 가로 넘침 없음·스크롤바 숨김을 확인했다.
- 실제 제공처 응답의 Content-Type 호환 문제를 발견해 문자열 수신 후 JSON 파싱·구조 검증으로 보완하고 관련 테스트 3개를 다시 통과했다.
- 전체 프론트엔드 빌드·모바일·장시간 호출 검증은 이번 단계에서 실행하지 않았다.
- DB 저장, 기사 전문 요약·LLM 연결은 이번 범위에 포함하지 않는다.

## 공식 규격
