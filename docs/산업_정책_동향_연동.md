# 산업·정책 동향 연동

## 구현 범위

- 산업통상부 공식 RSS의 최신 항목 10건을 가져오고 각 공식 상세 페이지의 본문을 추출한다.
- 수집 문서는 `policy_document`에 저장한다. `제공처 + 문서 ID`가 같으면 갱신하므로 재수집해도 중복 행이 생기지 않는다.
- 지원 종목 8개의 기업명과 산업 키워드로 1차 후보를 만들고, 임베딩 유사도와 AI 문맥 판정을 통과한 자료만 제공한다.
- 기업명이 직접 등장한 자료는 `기업 직접 언급`, 산업 키워드로 연결한 자료는 `산업 간접 관련`으로 구분한다.
- 정책브리핑 정책뉴스 목록은 6시간 간격으로 확인한다. 최신 10건 중 지원 종목의 기업명·산업 키워드가 있는 후보만 상세 페이지를 순서대로 요청한다.
- 정책브리핑 상세 페이지에 공공누리 제0·1·AI 유형이 명시된 텍스트만 저장한다. 제2·3·4유형, 유형 미표시 자료, 이미지·사진·영상·첨부파일은 저장하지 않는다.
- 정책브리핑 상세 요청 사이는 1.2초 간격을 두며 병렬 요청하지 않는다. 수집 실패 시 즉시 반복하지 않고 다음 시도를 6시간부터 최대 24시간까지 늦춘다. 프록시나 IP 변경으로 차단을 우회하지 않는다.
- 화면과 챗봇 답변에 제공처·원 발행기관·발표일·원문 링크를 표시한다.
- 수집은 사용자 조회와 분리된 백그라운드 작업이다. 서버 시작 15초 후 실행하고 이후 30분 간격으로 수집 필요 여부를 확인한다.
- 산업통상부는 30분, 정책브리핑 최신 목록은 6시간이 지나야 다시 수집한다. API 요청은 DB 자료만 조회하며 외부 수집을 시작하지 않는다.
- 정책브리핑 도입 전 자료는 최근 3개월을 목표로 백필한다. 30분마다 과거 목록 1페이지씩 처리하고 다음 페이지를 `policy_collection_state`에 기록해 재시작 후 이어간다.

조회 API는 다음과 같다.

```text
GET /api/stocks/{stockCode}/policies
```

## AI 답변 방식

FastAPI는 제목·도입부·본문 청크와 종목별 직접·산업 질의를 `text-embedding-3-small`로 임베딩하고 코사인 유사도를 계산한다. 임베딩은 후보의 의미상 근접도를 구하는 용도이며 최종 판정으로 사용하지 않는다. 이어서 기업이 정책 대상인지, 산업 전체에 적용되는지, 행사 참석자·강연자·수상자 수준의 단순 언급인지 문맥을 판정한다. 결과는 `policy_relevance`에 문서·종목별로 저장하므로 같은 분석을 반복하지 않는다. 별도 벡터 DB는 사용하지 않는다.

답변에는 다음 기준을 적용한다.

1. 정책과 주가의 인과관계를 단정하지 않는다.
2. 기업 직접 언급과 산업 간접 관련을 구분한다.
3. 발표·확정·시행 표현은 원문에 포함된 표현으로만 구분한다.
4. 산업통상부 또는 정책브리핑 원문 출처와 원 발행기관·발표일을 표시한다.
5. 관련도 점수가 낮은 자료는 제외한다.
6. `호재·악재`를 자동으로 확정하지 않는다.

## 제한

- 서버가 실행 중일 때만 정기 수집과 백필이 진행된다. 서버가 꺼져 있는 동안에는 수집하지 않는다.
- 최근 3개월 백필은 한 번에 모두 요청하지 않고 30분마다 한 페이지씩 처리하므로 완료까지 시간이 필요하다.
- 현재는 DB의 최근 문서 최대 500건을 관련도 분석 대상으로 사용한다.
- AI 서버를 사용할 수 없으면 공식 문서 수집은 계속되지만 미분석 자료를 화면에 노출하지 않고 다음 분석 주기에 다시 시도한다.
- 정책 상태 표시는 법적 효력 판정이 아니라 본문 표현의 단순 분류다. 최종 확인은 공식 원문을 기준으로 한다.
- 정책브리핑 RSS는 2026년 7월 중단됐으므로 웹 목록을 낮은 주기로 확인한다. 사이트 구조나 이용 정책이 바뀌면 수집을 중단하고 기존 DB 자료를 사용한다.
- 요청 간격과 재수집 제한은 사이트 부담과 차단 가능성을 줄이지만 IP 차단이 절대 발생하지 않는다고 보장하지 않는다.
