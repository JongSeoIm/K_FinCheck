# 실시간 시세 실행 가이드

## 구현 흐름

KIS KRX 실시간 체결(H0STCNT0) → 메시지 해석 → Kafka(stock-quotes-v1) → Spring 소비·최신 시세/봉 저장 → 브라우저 Push 또는 Polling.

- 기본 실시간 구독은 삼성전자 005930, SK하이닉스 000660 두 종목이다. 다른 종목은 기존 REST 현재가·기간별 시세 조회를 유지한다.
- KIS의 공용 시세만 구독한다. 개인 주문·계좌 체결통보와 주문 API는 사용하지 않는다.
- REST 접근토큰과 별도로 /oauth2/Approval 접속키를 서버에서 발급하고 메모리에서 재사용한다. 키·접속키·원본 인증 응답은 프론트엔드나 로그에 전달하지 않는다.
- 가격·거래량·등락률·일봉의 당일 값은 새 체결에 맞춰 갱신한다. Push는 0.5초 간격, Polling은 응답 후 2초 간격으로 같은 서버 상태를 읽는다.

## Docker 없이 로컬 실행

필요 조건: Java 21 JDK, Maven, 기존 backend/src/main/resources/application-local.yml의 본인 KIS 설정. 실제 설정 파일은 Git에서 제외한다.

1. 기존 8080 백엔드가 실행 중이면 해당 터미널에서 종료한다. 프론트엔드와 별도로 실행해야 한다.
2. 프로젝트 루트에서 PowerShell로 실행한다.

```powershell
.\start-realtime.ps1
```

이 스크립트는 테스트 소스를 컴파일하지만 기존 실제 KIS 통합 테스트를 실행하지 않는다. 개발용 내장 Kafka(KRaft)를 임의 로컬 포트에 띄우고 8080 Spring 서버를 연결한다. Maven이 PATH에 없으면 설치된 Maven 3.9 wrapper 배포본을 찾으며, 직접 지정할 수도 있다.

```powershell
.\start-realtime.ps1 -MavenCommand 'mvn.cmd 경로'
```

프론트엔드는 기존처럼 stock_dashboard에서 npm run dev로 실행한다. NEXT_PUBLIC_BACKEND_URL을 따로 설정하지 않았다면 localhost:8080을 사용한다. 다른 백엔드 포트를 사용할 경우 실행 전 프론트엔드 로컬 환경의 주소를 맞추고 개발 서버를 재시작한다. 이 주소에는 비밀값을 넣지 않는다.

종료는 실행 터미널에서 Ctrl+C로 한다. 내장 Kafka는 개발·시연용이며 저장소를 영구 보존하지 않는다. 일반 실행에는 아래 별도 Kafka 구성을 사용할 수 있다.

## Docker Kafka 사용

Docker와 Compose가 설치되어 있고 실행 중일 때 프로젝트 루트에서:

```powershell
docker compose up -d kafka
cd backend
mvn spring-boot:run "-Dspring-boot.run.profiles=realtime"
```

compose.yml은 apache/kafka:3.9.2 단일 브로커이며 9092는 localhost에만 노출한다. 개발용 내장 Kafka 실행 방식과 동시에 사용할 필요는 없다. Docker 구성은 이 환경에 Docker가 없어 직접 실행 검증하지 않았다.

## 화면과 데이터 범위

- Push/Polling 버튼으로 전달 방식을 바꿀 수 있다. Polling 요청이 KIS를 매번 새로 호출하지 않는다.
- 1초·5초·30초·1분·3분·5분·10분·15분·30분·60분은 서버가 연결 후 받은 체결을 기준으로 생성한다.
- 각 주기별 최근 120개 봉만 메모리에 보관한다. 거래가 없는 구간에 가짜 봉을 채우지 않는다.
- 첫 봉·연결이 끊긴 구간은 일부 체결만 포함할 수 있다. 화면의 '연결 후 수신분'은 전체 장중 이력이 아니라는 뜻이다. 재접속 시 누락 체결을 자동 복원하는 기능은 없다.
- 일·주·월·년은 기존 기간별 조회를 사용한다. 당일 일봉만 실시간 시세의 시가·고가·저가·누적 거래량으로 갱신한다. 주·월·년봉 실시간 합성은 이번 범위에 포함하지 않았다.
- 오래된 메시지와 동일/이전 누적 거래량을 거절한다. 일자 변경 시 누적 거래량이 다시 시작할 수 있다.
- 연결 대기, 체결 대기, 재연결, 설정 필요, Kafka 오류를 구분한다. 장외 무수신을 자동으로 휴장 확정하지 않는다.

## API와 설정

- GET /api/realtime/snapshot?interval=5: Kafka 소비 후 최신 시세·5초봉·상태 조회.
- WS /ws/quotes?interval=5: 같은 형태의 snapshot을 주기적으로 전송.
- snapshot 필드: type, relay, kafka, supportedSymbols, quotes, candles, intervalSeconds, serverTime.
- quote 필드: stockCode, price, priceChange, changeRate, open, high, low, volume(당일 누적), tradeVolume(해당 체결), businessDate, tradeTime, exchangeTime, receivedAt, source.
- 가격은 원, 거래량은 주, 체결 시각은 KIS 한국시간을 UTC Instant로 변환해 전달한다.
- backend/src/main/resources/application-realtime.yml에서 종목·토픽·그룹을 설정한다. stream.symbols는 초기 범위로 1~2개 종목만 허용한다.
- KAFKA_BOOTSTRAP_SERVERS는 별도 Kafka 주소, KIS_RELAY_ENABLED=false는 외부 KIS 수신 비활성화다.
- realtime 프로필을 사용하지 않으면 기존 REST 기능만 제공한다.
- WebSocket/CORS는 개발용 localhost·127.0.0.1의 3000·3001 포트를 허용한다. 여러 서버 인스턴스를 위한 상태 공유/인증 구성은 이번 로컬 개발 범위가 아니다.
