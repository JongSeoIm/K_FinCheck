# 조선비즈 RSS 목록·일회성 요약 설계

> 상태: 다음 구현 범위. 현재 코드에는 아직 반영되지 않았다.
>
> 확인 기준일: 2026-11-12

## 목적과 범위

조선비즈 공식 RSS가 제공하는 제목·링크·발행 시각을 이용해 최신 기사 목록을 보여주고, 사용자가 직접 선택한 기사 한 건만 요청 시점에 짧게 요약한다. 산업통상부·정책브리핑 자료처럼 기사 본문을 미리 수집하거나 DB에 저장해 RAG 검색 대상으로 사용하지 않는다.

```text
서버 실행
→ 조선비즈 공식 RSS를 일정 주기로 확인
→ RSS가 제공한 제목·링크·발행 시각만 메모리에 임시 보관
→ 제목에 종목명·별칭·산업 키워드 적용
→ 종목명이 있으면 직접 관련, 산업 키워드만 있으면 산업 관련으로 단순 분류
→ 제목·분류·출처·발행 시각·원문 링크를 화면에 표시

사용자가 기사 요약을 요청
→ RSS에서 받은 조선비즈 원문 링크인지 서버에서 확인
→ 해당 기사 원문을 요청 시점에 한 번만 조회
→ OpenAI에 전달해 2~3문장으로 요약
→ 출처·발행일·원문 링크와 함께 화면에 표시
→ 원문·중간 데이터·요약문을 저장하지 않고 폐기
```

## 산업·정책 자료와의 차이

| 구분 | 산업통상부·정책브리핑 | 조선비즈 RSS |
| --- | --- | --- |
| 목적 | 공식 산업·정책 자료 검색과 챗봇 답변 | 최신 RSS 기사 탐색과 선택 기사 요약 |
| 본문 수집 | 허용 조건을 통과한 공식 문서를 백그라운드 수집 | 사용자 요청 전에는 수집하지 않음 |
| 저장 위치 | MariaDB | RSS 메타데이터와 요약 모두 서버 메모리만 사용 |
| 관련도 | 키워드 후보, 임베딩 유사도, AI 문맥 판정 | RSS 제목 키워드의 단순 분류 |
| AI 사용 | 저장 문서를 검색해 정책 질문에 답변 | 사용자가 선택한 기사 한 건을 일회성 요약 |
| 대화 이력 | 정상 챗봇 답변 저장 | 기존 대화 이력에 저장하지 않음 |

## 화면 구성

기존 `산업·정책 동향` 패널은 유지하고 그 아래에 별도의 `최신 기사` 패널을 둔다. 두 자료는 수집·저장·AI 처리 방식이 다르므로 같은 목록이나 탭으로 합치지 않는다.

기사 한 건은 다음 정보를 표시한다.

- 분류 배지: `직접 관련` 또는 `산업 관련`
- 조선비즈가 제공한 원문 제목
- 출처 `조선비즈`와 발행 시각
- `원문 보기` 링크
- `2~3문장 요약` 버튼

분류 배지는 원문 제목에 문자열로 붙이지 않고 별도 UI 요소로 표시한다. 패널 상단에는 `제목 키워드 기준이며 본문 관련도 분석 결과가 아님`을 안내한다.

요약 버튼을 누르면 해당 항목 아래에 로딩 상태를 보여준 뒤 결과를 인라인으로 펼친다. 한 번에 한 기사만 펼치고, 종목 변경·새로고침·서버 재시작 시 요약 결과를 폐기한다. 요약 화면에는 `일회성 AI 요약·저장되지 않음`과 원문 링크를 함께 표시한다.

## 저장·처리 제한

- RSS가 제공하지 않은 값을 별도 크롤링으로 보완하지 않는다.
- 기사 본문, 본문 청크, 임베딩 벡터, 관련도 점수와 요약문을 DB나 파일에 저장하지 않는다.
- 모든 기사 본문을 미리 가져오거나 백그라운드에서 일괄 요약하지 않는다.
- 기사 본문을 화면에 재게시하지 않는다.
- AI 학습·파인튜닝 데이터로 사용하지 않는다.
- 기사 원문 URL은 RSS에서 받은 조선비즈 허용 주소인지 확인하고 임의 URL을 서버가 가져오지 않도록 한다.
- 원문 접근 실패·유료 또는 접근 제한 페이지는 우회하지 않고 요약 불가를 안내한다.
- 공개 서비스 적용 전에는 위 이용 방식도 조선비즈에 서면 확인한다.

## 구현 전 확정할 값

- RSS 재확인 주기와 메모리 만료 시간
- 제목 키워드 사전의 종목별 범위
- OpenAI 호출 비용 통제를 위한 로그인 요구 여부와 사용자별 호출 제한

이 값들은 요구사항이 확정되기 전까지 코드와 문서에서 완료된 기능처럼 표현하지 않는다.
