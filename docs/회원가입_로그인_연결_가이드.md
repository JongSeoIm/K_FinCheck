# 회원가입·로그인 및 계정별 관심 종목

## 구현

- `/login`: 아이디·비밀번호 입력, 회원가입 링크.
- `/signup`: 아이디·닉네임·비밀번호·비밀번호 확인.
- 기존 무채색·각진 입력창·버튼을 사용한다. 주식 화면 상단에는 로그인 또는 닉네임·로그아웃 메뉴를 표시한다.
- 로그인 후 원래 선택한 종목 화면으로 복귀한다. 복귀 주소는 홈 또는 6자리 종목 코드가 있는 홈 경로만 허용한다.
- 시세·차트·실적·산업 정책은 로그인 없이 조회 가능하다. 비로그인 상태에서 관심 종목 추가를 누르면 로그인 화면으로 이동한다.
- 회원은 기존 MariaDB app_user에 저장하며 BCrypt 비밀번호 해시를 사용한다. 서버도 입력 길이·형식·중복을 검사한다.
- 인증은 Spring Security 서버 세션 방식이다. HttpOnly·SameSite=Lax 쿠키, 30분 세션 만료, 로그인 시 세션 ID 변경, CSRF 토큰 검증을 적용한다.
- 기존 일반 헬스체크·DB 확인·시세·산업 정책·실적·WebSocket 경로는 유지한다.

## 관심 종목

- watchlist 테이블에서 로그인 회원의 user_id로만 조회·추가·삭제한다. 요청에 임의의 다른 회원 번호를 받지 않는다.
- 같은 종목은 중복 등록하지 않는다. 처음 관심 등록하는 지원 기업이 company에 없으면 기본 기업 정보를 추가한다. 기존 기업 정보는 덮어쓰지 않는다.
- 화면 초기 진입·로그인 후 목록을 불러오고, 로그아웃 시 화면 목록을 비운다. DB의 본인 목록은 유지한다.
- 기존 브라우저 로컬 저장 관심 종목은 자동으로 계정에 합치거나 삭제하지 않는다. 이제 계정 DB 목록을 사용한다.
- 관심 등록 기업은 현재 목업의 국내 기업 8개이며 기본 시장은 KOSPI다. 다른 종목 확장은 기업 등록 정책과 함께 진행한다.

## API

| 경로 | 메서드 | 동작 |
| --- | --- | --- |
| /api/auth/csrf | GET | 변경 요청용 CSRF 토큰 |
| /api/auth/signup | POST | 회원가입, 자동 로그인하지 않음 |
| /api/auth/login | POST | 세션 로그인 |
| /api/auth/me | GET | 현재 로그인 회원 |
| /api/auth/logout | POST | 세션 로그아웃 |
| /api/watchlist | GET | 본인 관심 종목 코드 목록 |
| /api/watchlist/{code} | POST / DELETE | 본인 종목 추가 / 삭제 |

프론트엔드는 credentials=include와 변경 요청의 CSRF 헤더를 사용한다. 인증 토큰·비밀번호를 localStorage에 저장하지 않는다. 로그인 상태는 새로고침 시 서버에서 다시 확인한다.

## 실행

기존 DB 설정을 유지하고 백엔드를 재시작한다. 실시간 시세를 함께 사용할 때는 기존 start-realtime.ps1 실행 방식을 사용한다. 프론트엔드는 기존 npm run dev로 실행한다. 프론트엔드와 백엔드는 localhost끼리 또는 127.0.0.1끼리 호스트를 맞춘다.

## 검증

- 실제 MariaDB에서 롤백되는 테스트 계정으로 회원가입·비밀번호 해시·로그인·세션 ID 변경·본인 조회·계정별 관심 종목 분리·중복 방지·삭제·로그아웃을 확인했다.
- CSRF 없는 요청·중복 아이디·잘못된 비밀번호·비로그인 관심 조회·잘못된 입력 거절을 확인했다.
- 새 통합 테스트 2개와 기존 헬스체크·시세·Kafka/WebSocket 테스트 4개, 총 6개 통과.
- 변경 프론트엔드 ESLint 및 별도 복사본의 Next.js Webpack 프로덕션 빌드 통과.
- 별도 검증 서버의 브라우저에서 비밀번호 확인 불일치, 실제 가입·로그인·SK하이닉스 화면 복귀, 관심 종목 등록·새로고침 유지·로그아웃 후 목록 비움을 확인했다.
- 브라우저 검증용 계정 한 개는 고유 ID·테스트 닉네임이 일치하는 행만 삭제했다. 해당 관심 목록은 외래키 연쇄 삭제로 정리했다. 자동 테스트에서 생성한 데이터는 롤백했다.
- 로그인 카드 400px, 가로 넘침 없음 확인. 다양한 모바일 크기·장시간 세션 운영 검증은 별도로 진행해야 한다.

## 이번 범위에서 제외

이메일 인증·소셜 로그인·비밀번호 찾기·관리자 기능·대화 이력 저장은 포함하지 않는다. 세션은 서버 메모리이므로 재시작하면 다시 로그인해야 한다.
