### 첫 번째 질문

> `onClick={setCount(count + 1)}`이거랑 `onClick={() => setCount(count + 1)}`이거 무슨 차이야? 그냥 임시로 함수 선언한 건가?

### 답변 내용 정리

첫 번째 코드는 버튼을 클릭하기도 전에 렌더링하면서 `setCount`가 바로 실행된다고 했다. 상태가 바뀌면 다시 렌더링되고 또 `setCount`가 실행될 수 있어서 문제가 생긴다.

두 번째 코드는 `setCount`를 바로 실행하는 것이 아니라, 클릭했을 때 실행할 함수를 전달하는 방식이라고 설명해 줬다. 처음에는 `() =>`가 위에 있는 `Counter` 함수를 뜻하는 줄 알았는데, 클릭할 때만 실행되는 새로운 함수라는 것을 알게 됐다.

그래서 프로젝트의 검색 결과 선택, 관심 종목 추가, 차트 기간 선택 버튼에도 아래처럼 함수를 전달했다.

```jsx
<button onClick={() => setRange('1D')}>1일</button>
```

<br>

### 두 번째 질문

> Hook이 정확히 뭐야? useState는 값 저장하는 거고 나머지는 잘 모르겠음

### 답변 내용 정리

Hook은 함수 컴포넌트에서 상태나 화면이 바뀐 뒤 실행할 작업 등을 사용할 수 있게 해 주는 함수라고 설명했다. 예를 들면 `useState`는 상태를 저장하고, `useEffect`는 렌더링 이후 API 요청이나 WebSocket 연결 같은 작업을 처리한다.

React는 Hook을 이름으로 구분하는 것이 아니라 호출되는 순서로 구분하기 때문에 조건문 안에서 Hook을 사용하면 렌더링할 때마다 순서가 달라질 수 있다고 했다. 그래서 Hook은 컴포넌트의 가장 위쪽에서 호출하고, 조건문은 그 아래에서 사용하는 방식으로 작성했다.

이 내용을 이해한 뒤 `useDebounce`, `useStockData`, `useFinnhubSocket` 같은 Custom Hook도 컴포넌트 최상위에서 호출했다.

<br>

### 세 번째 질문

> Zustand의 persist로 관심 종목을 저장했는데 새로고침하면 화면이 잠깐 달라지거나 Hydration 문제가 생기는 이유가 뭐야?

### 답변 내용 정리

Zustand의 `persist`는 관심 종목을 브라우저의 `localStorage` 에 저장한다. 하지만 Next.js가 서버에서 화면을 먼저 렌더링할 때는 `localStorage`에 접근할 수 없어서 관심 종목이 없는 상태로 HTML을 만든다.

이후 브라우저에서 저장된 관심 종목을 불러오면 서버에서 만든 화면과 브라우저 화면의 내용이 달라질 수 있다는 것을 알게 됐다.

이를 해결하기 위해 `useSyncExternalStore`를 이용한 `useHydrated Custom Hook`을 만들었다.

```jsx
export default function useHydrated() {
  return useSyncExternalStore(
    subscribe,
    () => true,
    () => false
  )
}
```

Hydration이 끝나기 전에는 관심 종목 개수를 `0`으로 표시하고 버튼을 비활성화하거나 `Skeleton UI`를 보여 주도록 구성했다.
또한 Zustand의 `partialize`를 사용해서 실시간 가격 전체를 저장하지 않고 관심 종목 목록만 저장했다.

```jsx
partialize: (state) => ({
  watchlist: state.watchlist
})
```

이를 통해 새로고침 후에도 관심 종목은 유지하면서 서버와 브라우저의 초기 화면 차이를 줄였다.

<br>

### 네 번째 질문

> Finnhub에서 API 키를 발급받고 `.env.local`을 만들어야 한다는데 강사님 GitHub 코드에 있는 API 키를 사용하면 안 돼? 내 거를 따로 발급받아야 하나?

### 답변 내용 정리

강사님 키처럼 다른 사람이 발급받은 키는 사용하지 않고 내 계정으로 새로 발급받는 것이 맞다고 했다. 공개된 키는 호출 한도가 이미 사용됐거나 나중에 막힐 수도 있고, 다른 사람의 키를 그대로 사용하는 것도 좋지 않기 때문이다.

발급받은 REST API 키는 `.env.local`의 `FINNHUB_API_KEY`에 저장하고, 브라우저에서 Finnhub를 바로 호출하지 않도록 Next.js의 `route.js`를 중간에 두는 방법을 알려 줬다.

```text
클라이언트
→ /api/stock/[symbol]
→ Next.js route.js
→ Finnhub API
```

이 구조를 검색, 현재가, 차트, 뉴스, 투자의견, 실적 API에 적용했다. `.env.local`은 GitHub에 올라가지 않도록 `.gitignore`에도 포함돼 있는지 확인했다.

<br>

### 다섯 번째 질문

> 더미 초기 차트에 WebSocket 실시간 점을 추가하고 싶은데 어떻게 함? 그래프가 실시간으로 값을 받아와 변동되는 걸 구현하고 싶은데. 강사님 13강 코드와 비슷한 파일 구조와 변수명을 참고해서

### 답변 내용 정리

화면을 처음 열었을 때는 Candle API 또는 기본 데이터로 차트를 먼저 보여 주고, WebSocket에서 새로운 체결가가 들어오면 배열 뒤에 새로운 점을 추가하는 방식으로 구성하면 된다고 했다.

처음에는 전광판과 차트에서 각각 WebSocket을 연결했는데, 무료 API 키에서 여러 연결을 만들면 한쪽 연결이 제대로 동작하지 않을 수 있다는 문제도 알게 됐다. 그래서 `Dashboard`에서 `useFinnhubSocket`을 한 번만 호출하고, 받은 데이터를 전광판과 차트에 props로 전달하도록 바꿨다.

또한 컴포넌트가 사라지거나 구독 종목이 바뀔 때는 아래 작업이 필요하다고 했다.

```jsx
return () => {
  socket.send(JSON.stringify({ type: 'unsubscribe', symbol }))
  socket.close()
}
```

<br>

미국 시장이 닫혀 있으면 실제 주식 체결이 들어오지 않아 차트가 멈춘 것처럼 보였다. 수업 시연을 위해 강사님 코드에 있던 `BINANCE:BTCUSDT`를 구독하고, BTC 가격의 변동률만 선택 종목 가격에 적용하는 시연 모드도 따로 만들었다.

### 여섯 번째 질문

> 아 마지막으로 5초, 30초, 1분 이렇게 그래프 할 수 있어? 기존 1일, 1주, 1개월에 더 추가하고 1년도 볼 수 있게 하고 싶어.

### 답변 내용 정리

5초, 30초, 1분처럼 짧은 구간은 Candle API를 계속 호출하는 것보다 이미 받은 WebSocket 체결 기록을 시간으로 잘라서 보여 주는 것이 낫다고 했다.

그래서 짧은 구간은 WebSocket 데이터를 사용하고, 긴 구간은 다음과 같이 Candle API 데이터를 사용했다.

- 5초, 30초, 1분: WebSocket 체결 기록
- 1일: 5분 단위 데이터
- 1주: 1시간 단위 데이터
- 1개월: 일 단위 데이터
- 1년: 주 단위 데이터

버튼을 눌렀을 때 글자만 바뀌는 것이 아니라 실제 그래프의 데이터와 X축이 달라지는 것도 확인했다.

## 7. 프롬프트를 다시 작성한 경험

### 처음에 한 질문

> UI는 굳이 막 신경써서 만드는 것보다는 기능만 잘 작동하게 하는 게 나을 거 같아.

### 처음 결과에서 아쉬웠던 점

처음에는 상세보기를 누르면 다른 페이지가 열렸고, 화면 중앙만 사용해서 양쪽에 빈 공간이 많이 남았다. 둥근 카드, 그림자, `Market Board`, `US Market` 같은 장식도 들어가서 내가 수업 시간에 만든 프로젝트보다는 AI가 만든 화면처럼 보였다.

그래프도 미국 시장이 닫힌 시간에는 움직이지 않았기 때문에 정상적으로 연결된 것인지 확인하기 어려웠다.

<br>

### 다시 구체적으로 질문한 내용

> 상세보기를 눌러 다른 페이지로 이동하는 방식은 빼고, 종목을 선택하면 같은 화면의 내용이 바뀌게 해 줘. 화면 중앙만 사용하지 말고 왼쪽에는 종목 정보, 차트, 뉴스를 놓고 오른쪽에는 관심 종목, 전문가 투자의견, 실적을 배치해 줘. 둥근 카드나 그림자, MB 로고, US Market처럼 의미 없는 장식은 삭제하고 직선 테두리 위주로 수정해 줘. 실제 주식 차트가 움직이지 않는 시간에는 강사님 13강처럼 WebSocket 동작을 확인할 수 있는 BTC 시연 모드를 따로 만들어 줘.

### 다시 질문한 뒤 달라진 점

- 종목을 선택해도 다른 페이지로 이동하지 않게 됐다.
- 좌우 영역을 사용해서 빈 공간이 줄었다.
- 둥근 카드와 의미 없는 장식을 제거했다.
- 실제 주식과 BTC 시연을 직접 선택할 수 있게 됐다.
- 뉴스, 관심 종목, 투자의견, 실적을 같은 화면에서 확인할 수 있게 됐다.

처음처럼 단순히 `UI를 수정해 줘`라고 질문했을 때보다 어떤 기능을 없앨지, 화면을 어떻게 나눌지, 실시간 데이터는 어떻게 확인할지 구체적으로 적었을 때 원하는 결과에 더 가까워졌다.
